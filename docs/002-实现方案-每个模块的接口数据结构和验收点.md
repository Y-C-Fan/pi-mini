## 1 分层与依赖方向

依赖只允许单向：`modes → agent → session → ai`，`agent → tools`。
反过来 import 就是设计错了。session 不知道 agent 存在；ai 不知道工具是什么。

## 2 先定死的数据结构（动笔前抄一遍）

会话文件：`~/.pi-mini/sessions/<id>.jsonl`，一行一条 JSON，UTF-8，追加写。

首行（仅一次）：
```
{"type":"session","version":1,"id":"<uuid>","cwd":"<abs path>","createdAt":"<ISO8601>"}
```

消息 entry：
```
{"id":"<8位hex>","parentId":"<8位hex>|null","timestamp":"<ISO8601>",
 "type":"message","message":{"role":"user|assistant|system","content":[...]}}
```
`content` 照 OpenAI 形状：文本块 `{"type":"text","text":"..."}`；assistant 的调用块 `{"type":"toolCall","id":"call_x","name":"read","arguments":{...}}`；工具结果 `{"type":"toolResult","toolCallId":"call_x","output":"...","isError":false}`。

压缩 entry：
```
{"id":"...","parentId":"...","timestamp":"...","type":"compaction",
 "summary":"<6段纯文本>","firstKeptEntryId":"<8位hex>","tokensBefore":12345}
```

工具表（进程内，不落盘）：
```
TOOLS = {name: {"description": str, "parameters": <JSON Schema>, "run": callable}}
```

事件（内存流，不落盘，7 类）：
- `turn_start {turn:int}`
- `text_delta {text:str}`
- `tool_call {id,name,arguments}`
- `tool_result {id,output,isError}`
- `usage {inputTokens,outputTokens}`
- `done {reason:"stop|max_turns|aborted|error"}`
- `error {message}`

关键区分：entry 是持久真相，event 是瞬时通道。事件永远不写进会话文件。

## 3 各模块

### 3.1 ai/client.py

职责：把一次模型请求变成一个事件流。唯一懂 HTTP 和 SSE 的地方。

接口：`stream_chat(model: str, messages: list, tools: list) -> Iterator[Event]`

必须自己处理的流式细节：
1. 按 `\n` 读行，维护缓冲区，跨包残行留到下次拼接（SSE 不保证一行一次 recv）。
2. 空行是帧分隔；`data: [DONE]` 结束。
3. `choices[0].delta.content` 直接产 `text_delta`。
4. `delta.tool_calls` 是**分片**：按 `index` 归并到同一个调用，`id`/`name` 只在第一片出现，`arguments` 是字符串碎片要顺序拼接，流结束才 `json.loads`。
5. 末帧可能带 `usage`，缺失就自己估。
6. HTTP 非 200 先读 body 再抛，错误体常是 JSON。

边界：超时 120s；非 SSE 响应（服务端直接返回 JSON）要当错误处理；空 choices 数组跳过。
不做：重试、多 provider、图片——P3 再说。

验收（fixture 回放，不走网络）：三段文本 + 一个分两片的 tool_call，断言得到 3 个 `text_delta`、1 个 `tool_call`、arguments 是完整 dict。

### 3.2 agent/loop.py

职责：turn 循环与状态。唯一知道"该不该再来一轮"的地方。

接口：`run(messages, tools) -> Iterator[Event]`，外部给初始消息，它负责迭代。

循环规则（照 Pi 的语义）：
1. 一轮 = 一次请求 + 执行该响应里的全部工具调用。
2. 再来一轮的条件：本轮有 tool_call，或队列里有待发消息。两者都没有就 `done`。
3. 工具串行执行，逐个产 `tool_call` 与 `tool_result`。
4. 工具失败不抛：转成 `{output: "Error: ...", isError: true}` 回喂模型。
5. `stopReason == "length"` 时该响应的 tools 一个都不执行，全部回错误。
6. 安全阀：`max_turns`（默认 32）到就 `done{reason:"max_turns"}`。Pi 没有这个，我们加。
7. abort 标志：每轮开始时检查，置位就 `done{reason:"aborted"}`，已产生的历史不删。

难点在这里不在 HTTP：assistant 消息必须**原样**带 tool_calls 回传，紧跟 tool 结果消息，否则 OpenAI 兼容端点报 400。顺序错了排查很久。

验收 4 条：单轮无工具；一轮带 2 个工具；工具抛错后模型收到 isError 的文本；max_turns 命中。

### 3.3 tools/

职责：4 个工具 + 注册表。

- `read(path, offset?, limit?)`：文本先到为准 2000 行或 50KB；超限追加 `[Showing lines a-b of N. Use offset=X to continue.]`。
- `write(path, content)`：自动建父目录。
- `edit(path, edits:[{oldText,newText}])`：oldText 必须在原文唯一且互不重叠；不唯一直接失败并回错误文本。
- `bash(command, timeout?)`：`subprocess` 跑 bash，超时杀掉；取 stdout+stderr 尾部 2000 行/50KB；exitCode≠0 即 isError。

路径安全：所有相对路径按进程 cwd 解析，拒绝 `..` 越出 cwd。

验收：edit 非唯一文本时返回错误而不是猜；bash 超时；read 大文件带续读提示。

### 3.4 session/store.py

职责：JSONL 树的读写与分支重建。

接口：`append(entry)`、`entries()`、`leaf()`、`set_leaf(id)`、`build_context(leaf_id) -> list[message]`、`fork(from_id)`、`list_sessions()`。

- 追加写后必须 flush；崩溃留下的半行在读时跳过。
- `build_context`：从 leaf 逆走到 root，反转成正序，转成模型消息。
- 若路径中含 compaction：用最新那条的 summary 当第一条，跳过它之前的所有 message，从 `firstKeptEntryId` 起取到 compaction 前，再接 compaction 之后的全部 entry。
- 同一文件里多条分支靠 leaf 指针切换，不复制数据。

验收：写两条分支，切 leaf 后 build_context 内容不同；压缩后旧 entry 仍在文件里。

### 3.5 session/compaction.py

职责：上下文超预算时插摘要，不删历史。

- 估算 token：`ceil(chars/4)`；有 usage 回报时从回报处往后才估。
- 触发：`估算 > 窗口 − 16384`，或手动 `--compact`。
- 切点：从尾部往回累计到 20000 停止，且不切在 tool 结果中间。
- 摘要 prompt 固定六段：Goal / Constraints & Preferences / Progress / Key Decisions / Next Steps / Critical Context。
- 写一条 compaction entry，`tokensBefore` 记压缩前估算值。

验收：造 30 轮假历史，断言发生一次压缩、文件里 message 一条没少、下一次请求的消息条数明显下降。

### 3.6 modes/

- print：消费事件流打文本，只输出 `text_delta` 与 `tool_result` 的短提示。
- json：一拍一行 JSONL，事件原样。
- （P4）interactive：同一事件流换渲染器，不重写 agent。

验收：同一个 run，两种模式输出的事件条数一致。

## 4 顺序（每步都留可跑的入口）

1. 数据结构 + session 追加读写（无模型调用，纯本地可测）。
2. ai/ 客户端 + fixture 回放。
3. tools/ 四个 + 注册表。
4. agent/ 循环，接 fake provider。
5. print / json 两个模式，接真模型。
6. compaction。
7. 收尾：`--continue`、`--resume`、`--list`。

先做 1、2 的理由：都无需网络即可验证，可以先把测试和数据结构焊死。

## 5 与 Pi 的两处有意偏离（写进 README，别偷偷改）

1. 加 `--max-turns`：Pi 靠队列和 finishTurn 自然终止，我们没那套编排，需要硬阀门。
2. 工具串行：Pi 支持并行且按原序回填，我们单线程够用，省下并发正确性这一整块。

## 6 自己写必撞的坑

- tool_calls 分片按 `index` 归并，不能按出现顺序（并行调用会交错）。
- SSE 读行要自建缓冲，`urllib` 的 readline 在分块边界可能被截断。
- assistant 带 tool_calls 的消息不能改写，必须原样回传。
- 工具结果消息的 `tool_call_id` 必须与调用 id 对上，顺序不能乱。
- JSONL 追加要 flush，否则进程被杀时丢最后一条，看起来像"模型忘记刚才做了什么"。
- Windows 下 bash 工具走 `subprocess` 时要显式给 shell 和 cwd，别依赖当前目录。
